Start your Claude 5-hour usage window before you start work

Claude Pro and Max limits reset 5 hours after your first message. claude-warmup sends one tiny message early, so the reset lands in the middle of your workday instead of at the end. It also shows your session and weekly usage.

Why warm up the Claude 5-hour window?

Claude's session limit is counted in 5-hour windows that begin with your first message. Start at 9:00 and hit the limit at noon, and you wait until 14:00. Open the window at 6:00 instead, and you get a fresh one at 11:00.

Without warm-up

14:00 → 19:00
060912151821

One window covers most of the day. Hit the limit at noon and you are stuck until 14:00.

With a 6:00 warm-up
ping 6:00 → 11:00
11:00 → 16:00
16:00 → 21:00
060912151821

A fresh window at 11:00, right when the morning's work has used up the first one.

Your limits do not grow. The resets just move to where they help.

You can warm up the window with a fixed cron job or a hosted CI runner too. claude-warmup is built to need less trust and less guessing.

How it works

  1. The OS scheduler (launchd, systemd or cron, Task Scheduler) runs a check every 5 minutes.
  2. If the current window is still running, the check does nothing. No Claude call at all.
  3. Otherwise it reads usage with Claude Code's local /usage command: 0 tokens, $0.
  4. Only when no window is active does it send hi to haiku through the official claude CLI, with tools, MCP and hooks turned off.
  5. It records when the new window ends and sleeps until then. "Every 5 hours" follows the real window, not a clock.

Never reads credentials

Sign-in stays with the official Claude Code CLI. API-key variables are stripped, so nothing is billed to an API key.

Zero dependencies

Plain Node.js 18+, small enough to read in one sitting. MIT licensed.

Working hours

Limit pings to 06:00-23:00, weekdays, or any days you choose.

Install

You need Node.js 18+ and the Claude Code CLI, logged in with a Pro or Max subscription.

npm install -g github:jungtaejoon/claude-warmup
claude-warmup install

Suggested: if you start at 9, let pings begin at 6.

claude-warmup config hours 06:00-23:00

Run it on a free server

Computer not on all day? Put it on any always-on Linux machine: a free cloud VM such as Oracle Cloud Always Free, a cheap VPS or a Raspberry Pi. The window belongs to your account, so any machine can send the ping.

curl -fsSLO https://raw.githubusercontent.com/jungtaejoon/claude-warmup/main/scripts/server-setup.sh && bash server-setup.sh --timezone America/New_York

It installs Node.js, Claude Code and claude-warmup into ~/.local, walks you through a browserless login and turns on a systemd timer. Server guide

FAQ

When does the Claude 5-hour usage limit reset?

5 hours after the first message of a window. First message at 9:00 means a reset at 14:00. A warm-up at 6:00 moves it to 11:00. More in the Claude usage limit reset guide.

Does this give me more Claude usage?

No. Same limits, placed better for your working hours.

How much usage does the warm-up cost?

Almost none. Checks use the local /usage command (0 tokens). The ping is one short haiku message per window.

Can I run it while my computer is off?

Yes, on a server. See Run it on a free server.

Does it read my Claude password or token?

No. The official claude CLI handles all sign-in.

Is this allowed?

It is a tiny request made with your own account through the official Claude Code CLI. Read Anthropic's terms and decide for yourself.
