Claude 5시간 창을 늘 켜 두면, 5시간을 꽉 채워 기다릴 일이 줄어요

Claude Pro·Max 한도는 창의 첫 메시지 후 5시간이 지나야 리셋됩니다. 보통은 내 첫 메시지가 그 시계를 새로 시작해서, 자리에 앉는 순간부터 5시간을 꽉 채워야 하죠. claude-warmup은 창이 끝나는 대로 바로 새 창을 열어 시계가 늘 돌아가게 해요. 언제 시작하든 다음 리셋까지 5시간보다 짧아요. 세션·주간 사용량도 한눈에 보여 줘요.

왜 Claude 5시간 창을 늘 켜 둬야 하나요?

Claude 세션 한도는 앞 창이 끝난 뒤 첫 메시지를 보낸 순간부터 5시간 단위로 계산됩니다. 열린 창이 없으면 내 첫 메시지가 5시간 시계를 새로 시작해요. 9시에 시작해서 12시에 한도에 걸리면 14시까지 기다려야 하죠. 내가 오기 전에 이미 창이 흐르고 있었다면, 그 5시간 중 일부는 벌써 지나 있어요.

내 첫 메시지가 5시간을 통째로 시작해요. 12시에 한도에 걸리면 14시까지 막힙니다.

창이 끊김 없이 이어져요. 9시에 앉으면 지금 창은 이미 3시간이 지나 있어서 다음 리셋은 14시가 아니라 11시예요. 점심 먹고 13시에 시작해도 18시가 아니라 16시에 리셋돼요.

한도가 늘어나는 건 아니에요. 언제 앉든 5시간을 처음부터 꽉 채워 기다리는 일이 없어질 뿐이에요.

다른 방법과 뭐가 다른가요?

정해진 시각에 도는 cron이나 클라우드 CI로도 창을 미리 열 수 있어요. claude-warmup은 로그인 정보를 맡기지 않고, 시각을 맞추느라 고민하지 않아도 되게 만들었어요.

동작 방식

  1. OS 스케줄러(launchd, systemd·cron, 작업 스케줄러)가 5분마다 확인을 실행합니다.
  2. 지금 창이 아직 진행 중이면 아무것도 하지 않아요. Claude를 아예 부르지 않습니다.
  3. 그렇지 않으면 Claude Code의 로컬 /usage 명령으로 사용량을 확인해요. 토큰 0, 비용 $0입니다.
  4. 열린 창이 없을 때만 공식 claude CLI로 haiku에 hi를 보냅니다. 도구·MCP·훅은 모두 끕니다.
  5. 새 창이 끝나는 시각을 기록하고 그때까지 쉽니다. "5시간마다"는 시계가 아니라 실제 창 기준이에요.

로그인 정보를 읽지 않아요

로그인은 공식 Claude Code CLI가 맡아요. API 키 변수는 지워서 API 요금이 나가지 않습니다.

의존성 0개

Node.js 18+만 있으면 되고, 한 번에 다 읽을 수 있을 만큼 작아요. MIT 라이선스.

작업 시간 지정

06:00-23:00, 평일만 등 원하는 시간과 요일에만 핑을 보내요.

피크 시간

가장 바쁜 시각(예: 14:00, 11:30 weekdays)을 정하면 그때 창이 딱 리셋되게 맞춰요.

설치

Node.js 18 이상과, Pro·Max 구독 계정으로 로그인한 Claude Code CLI가 필요합니다.

npm install -g github:jungtaejoon/claude-warmup
claude-warmup install

창을 켜 둘 시간대를 정하세요. 예를 들어 이른 아침부터 밤까지:

claude-warmup config hours 06:00-23:00

무료 서버에서 돌리기

컴퓨터를 하루 종일 켜 둘 수 없다면, Oracle Cloud Always Free 같은 무료 클라우드 서버나 라즈베리 파이처럼 늘 켜져 있는 Linux 기기에 설치하세요. 사용량 창은 계정 단위라 어느 기기에서 핑을 보내도 됩니다.

curl -fsSLO https://raw.githubusercontent.com/jungtaejoon/claude-warmup/main/scripts/server-setup.sh && bash server-setup.sh --timezone Asia/Seoul --lang ko

Node.js, Claude Code, claude-warmup을 ~/.local에 설치하고, 브라우저 없는 로그인을 안내한 뒤 systemd 타이머를 켜 줍니다. 서버 설치 안내

자주 묻는 질문

Claude 5시간 사용량 한도는 언제 리셋되나요?

창의 첫 메시지로부터 5시간 뒤예요. 그 첫 메시지가 내가 9시에 보낸 것이면 14시에 리셋돼요. claude-warmup을 쓰면 시작할 때 이미 창이 흐르고 있어서 리셋이 더 빨리 와요. 자세한 내용은 Claude 사용량 한도 리셋 가이드에 있어요.

가장 바쁜 시간에 맞춰 리셋되게 할 수 있나요?

네. claude-warmup config peak 14:00으로 정하면 14시에 창이 딱 리셋되도록 맞춰요. 이때 핑은 9시, 4시처럼 피크에서 5시간씩 거슬러 간 시각에만 나가요. 내가 다른 시각에 직접 창을 시작했다면 그 창은 옮길 수 없고, 끝난 뒤 다시 맞춰요. 요일도 정할 수 있어요: config peak 11:30 weekdays.

사용량이 늘어나나요?

아니요. 한도는 같아요. 5시간을 꽉 채워 기다릴 일이 드물어질 뿐이에요.

워밍업은 사용량을 얼마나 쓰나요?

거의 안 써요. 확인은 로컬 /usage 명령(토큰 0)이고, 핑은 창마다 haiku 짧은 메시지 하나예요.

컴퓨터를 꺼 둬도 되나요?

네, 서버에서 돌리면 됩니다. 무료 서버에서 돌리기를 보세요.

Claude 비밀번호나 토큰을 읽나요?

아니요. 로그인은 전부 공식 claude CLI가 처리해요.
