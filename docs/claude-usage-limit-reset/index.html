When does the Claude usage limit reset?

Guide · Claude Pro and Max · Updated November 2026

If you use Claude Pro or Max all day, you have probably seen "limit reached, resets at 14:00" right in the middle of your work. This guide explains how the reset is timed, how to see your own reset time, and how to move it to a better spot.

Short answer: the session limit resets 5 hours after the first message of a window. Send your first message at 9:00 and it resets at 14:00. Send one at 6:00 and it resets at 11:00.

How the 5-hour window works

  • A window starts with your first message after the previous one has ended. It does not start at a fixed clock time. (Claude help center)
  • Everything you do in that window counts toward one limit: Claude on the web, the desktop and mobile apps, and Claude Code all share it.
  • When the window ends, the session limit resets fully. The next message starts a new window.
  • There is also a separate weekly limit. Moving your 5-hour windows does not change it.

How to check your reset time

  • Claude Code: run /usage. It shows the current session and weekly usage, each with its reset time.
  • claude.ai: open Settings and look at the usage section.
  • claude-warmup: run claude-warmup in a terminal. It prints the same numbers as progress bars, with "resets 11:00 (in 2h 17m)".

Why the default timing hurts

Most people send their first message when they start work. That puts the whole morning in one window. A busy morning uses it up around noon, and the reset comes in mid-afternoon, so you lose the most productive hours waiting.

How to make the reset land while you work

Start the window before you start working. If you start at 9:00, open the window around 6:00:

  • 6:00 to 11:00: the first window. You only use the 9:00 to 11:00 part of it.
  • 11:00: a fresh window, just as the morning's work would have hit the limit.
  • 16:00: another fresh window for the late afternoon.

You can do this in three ways:

  1. By hand. Send any short message from your phone when you wake up. Free and simple, but easy to forget.
  2. With a fixed scheduled job. A cron job that runs claude -p hi --model haiku at 6:00. It works, but it fires at fixed times even when a window is already open, and hosted runners need your token copied into their secrets.
  3. With claude-warmup. It checks every 5 minutes with the local /usage command (0 tokens) and sends one tiny haiku message only when no window is open. It runs on your own machine or server and never reads your credentials.

Set it up with claude-warmup

You need Node.js 18+ and the Claude Code CLI, logged in with Pro or Max.

npm install -g github:jungtaejoon/claude-warmup
claude-warmup install
claude-warmup config hours 06:00-23:00

If your computer is off in the early morning, run it on a free always-on server instead. See the server setup.

Things to keep in mind

  • This does not give you more usage. It only changes when the resets happen.
  • The warm-up message itself uses a tiny amount of the new window.
  • Your weekly limit still applies.
